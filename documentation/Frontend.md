# Virasat Setu Frontend Architecture and User Interface Specification:

This document details the architectural layout, component hierarchy, client state management and user experience design powering the frontend presentation layer of Virasat Setu.

Virasat Setu Frontend Technology Stack:
1. Presentation Markup: Semantic HTML5 Single Page Application Architecture.
2. Utility Styling Framework: Modern Tailwind CSS for Responsive Layouts and National Palette Tokens.
3. Iconic Symbolism: FontAwesome 6 Pro Vector Iconography Suite.
4. Client State Controller: Native Asynchronous Vanilla JavaScript (app/static/app js).
5. Typography: Google Fonts Inter and Devanagari Bilingual Display Typography.
6. Serverless Delivery: Zero Compilation Static Asset Pipeline Mounted Directly via FastAPI.


## Frontend Architectural Principles:

The client interface is engineered to adhere to strict public digital infrastructure principles:

1. Zero Compilation Pipeline: The interface requires no complex Webpack, Vite or Node js build step in production. All HTML, CSS and JavaScript files are delivered directly by the ASGI application engine, ensuring immediate loading with zero build fragility.
2. Low Bandwidth Accessibility: Formatted with lightweight markup, SVG icons and utility classes, the portal loads rapidly across varying network bandwidths typical of rural and semi urban India.
3. Cognitive Load Minimization: Citizens navigating bereavement are guided by clear visual progress steppers, plain language instructions and helpful empty states rather than dense bureaucratic procedures.
4. Role Adaptive Presentation: The interface dynamically transforms its navigation bar, operational consoles, action buttons and metric cards based on the authenticated user role.
5. Sovereign Chromatic Identity: Styled with the official national tricolor accent bar, Sovereign Navy, Radiant Saffron, Growth Emerald and Heritage Gold.

5. Authentication Action Cluster: Displays citizen profile pill and Sign Out button when authenticated, or Sign In and Register triggers when unauthenticated.

### 2. Main Navigation Bar:

The navigation bar dynamically partitions access based on user role:

1. Home Tab: Public landing view explaining the four step discovery workflow.
2. Citizen Dashboard Tab: Visible to citizens, providing metric summaries of submitted records and active claims.
3. Register Deceased Tab: Visible to citizens, housing the four section civil death registration form.
4. Discovered Assets Tab: Visible to citizens, displaying candidate financial matches generated by the matching engine.
5. Claim Tracking Tab: Visible to citizens, rendering five stage visual progress steppers for filed claims.
6. Viru (AI Copilot) Tab: Accessible to all users, launching the interactive legal succession advisor dialog.
7. Browse Database Tab: Exclusively visible to administrators, allowing exploration of the central financial repository.
8. Administrator Dashboard Tab: Exclusively visible to administrators, providing oversight metrics, pending verification queues and user provisioning.
9. Institutional Desk Tab: Visible exclusively to bank and insurance representatives, presenting assigned incoming claim queues.

### 3. Citizen Family Dashboard Console:

1. Overview Metric Cards: Four dynamic cards displaying Registered Family Members, Discovered Unclaimed Wealth (in Rupees), Active Financial Claims, and Completed Settlements.
2. Deceased Records Directory: Table displaying submitted family records with civil status pills (Pending Verification, Verified, Rejected) and direct action triggers.
3. Discovered Assets Summary: Highlights top potential bank deposits, insurance policies and mutual fund folios.
4. Quick Action Banners: Direct shortcuts to register new deceased relatives, initiate asset discovery or consult Viru.

### 4. Deceased Civil Registration Console:

The registration console organizes civil record submission into four structured sections:

1. Section 1 Deceased Personal Details: Captures full legal name, date of birth, date of death, gender dropdown, last known city and last known federal state.
2. Section 2 Municipal Civil Certificate Information: Captures municipal death certificate reference number, registration date, issuing municipal corporation, and Permanent Account Number (PAN). Submitting a certificate reference code is completely optional.
3. Section 3 Submitter and Claimant Details: Captures applicant legal name, mobile number, email address, relationship with deceased dropdown (Son, Daughter, Spouse, Brother, Sister), and claimant capacity dropdown (Nominee, Legal Heir).
4. Section 4 Document Attachment (Optional): File upload container accepting digital copies of death certificates or succession documents. Submission proceeds successfully even when no document is attached.

### 5. Discovered Assets and Matching Console:

1. Deceased Selection Bar: Dropdown selector allowing family members to toggle between multiple registered deceased relatives.
2. Aggregate Wealth Card: Highlights total discovered financial value and count of identified assets broken down by Banks, Insurance and Mutual Funds.
3. Candidate Match Cards: Each identified financial holding is rendered in an individual card featuring:
   * Holding Category Badge (Bank Deposit, Life Insurance Policy, Mutual Fund Folio).
   * Institution Legal Title and Scheme Category.
   * Masked Account, Policy or Folio Identifier.
   * Asset Holder Name on Institutional Record.
   * Approximate Asset Valuation in Indian Rupees.
   * Dormancy Tenure and Unclaimed Status.
   * Circular Match Confidence Pill (Scores between 0 and 100 points, labeled Strong Potential Match or Requires Manual Review).
   * Transparent Scoring Breakdown: Attributed point itemization across Identity Reference, Name Similarity, Birth Date Alignment and Nominee Location Connection.
   * Action Trigger: Prominent Initiate Claim button for unclaimed holdings, or status indicator for holdings with active claims.

1. Five Stage Visual Lifecycle Stepper: Horizontal progress bar mapping claim status across:

## Client State Controller Architecture (app js):

The client application logic is implemented in native vanilla JavaScript adhering to modular functional principles:

1. Global Session State: Maintains currentUser profile, currentToken JWT string, activeDeceasedId pointer and currentRenderedMatches cache.
2. Authenticated Fetch Wrapper (apiFetch): Centralized wrapper handling JSON serialization, Authorization Bearer headers, custom X Requested With verification headers, silent error handling and automatic redirection on HTTP 401 Unauthorized.
3. Tab Switching State Machine (switchTab): Hides and displays corresponding DOM tab containers, updates active navigation styling and triggers contextual data loading.
4. Real Time Debounced Search: Implements setTimeout debouncing on administrative search inputs to prevent excessive DOM re renders during rapid typing.
5. Contextual UI Refresh (updateUIForUser): Synchronizes navigation tab visibility, user display name pills, and role specific controls following authentication transitions.
6. Cross Site Scripting Sanitization (escapeHTML): Encodes untrusted dynamic strings into secure HTML entities prior to interpolating templates into DOM innerHTML.
7. Toast Notification Controller (showToast): Dispatches animated toast alerts in the bottom right viewport with color coding for success, error, warning and informational events.
